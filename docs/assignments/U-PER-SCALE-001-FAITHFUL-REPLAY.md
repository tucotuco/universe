## Objective and governing decision

Prove that **initial authoritative state + atomic property changes + committed Events (including Events with no property changes) + complete Save snapshots** can support a *faithful replay* of a real native Encounter without the Arena application. The replay must preserve not only the final state but also the chronological sequence of meaningful Events, their causal relationships, observer-owned facts within the supported scenario, deterministic RNG results in this pinned same-version test, and state at each intermediate boundary. Literal Event/Effect identifier equality across independently instantiated replays is **not** a persistence requirement.

Distinguish and implement/test **both**:

1. **Historical reconstruction / playback:** Start from the recorded initial state, apply time-ordered committed change sets, and expose the state and Event history at any tested boundary **without invoking native combat/Action resolution**. An old Action is reported as historical evidence, not performed again. Preserve successful, unsuccessful or zero-diff Events and simultaneous-action batches.
2. **Deterministic native re-execution:** Start from the same initial native facts, rules/definitions and RNG ownership/cursor, feed the *recorded external Action/Choice declarations/decisions* at the correct times, and advance through ordinary native `Encounter.step()`/transactional publication. Compare its actual committed outcomes with the original history at **each boundary**. Do not inject recorded outcomes, rolls, property deltas or post-hoc state corrections into the evaluator. If a necessary external decision or nondeterministic input was not captured, report that as a concrete fidelity gap rather than bypassing it.

This deterministic native re-execution is **only a current-version validation tool for the initial-state/delta/Event model**; no exact simulation replay across rule, source, or RNG-algorithm changes is required or implied. Stored historical facts must be interpretable under their declared schema/semantics, but re-running changed rules to obtain old outcomes is not a goal.

**Identifier semantics:** Distinguish (a) semantic identity of the historical Event or Effect *within one logical Encounter* from (b) its particular serialized identifier string and (c) Python object identity. Causal links, source/target links, references from other Events/Effects, and per-boundary correspondence must survive reconstruction. Literal IDs may remain unchanged, or a complete, consistent one-to-one ID mapping may be applied when reconstructing or comparing *independent* instances. Do not reject a valid reconstructed timeline merely because its generated IDs differ. For Save/Load of the **same logical Encounter**, do not break any references already persisted or externally visible; retain IDs where needed or validate a consistent remapping across all in-scope references. The prototype does not need a new general renaming facility to prove this: semantic comparison modulo a documented consistent mapping is sufficient.

The separate **fresh-process resume** demonstration from the previous assignment remains the validation that future simulation can continue from a selected checkpoint. Include a replay-to-checkpoint → fresh-process native continuation check where it fits the existing bounded closure; do not make a new general restore framework a prerequisite. Recording/replaying historical facts and restoring a native process are complementary obligations, not the same operation.

## Required scenario and evidence

Build on `examples/encounter_delta_headless.py`, `examples/native_headless_resume.py`, and existing focused tests. Do not use `GeneratedArenaSession`, browser/server/controller/Chrome, or `npcgen`; keep all Actions evaluated by the authoritative native engine.

Use an authored lawful **two-Being native Encounter** with a fixed seed and documented initial facts, and exercise the following in a single coherent timeline where practicable (otherwise explicitly labeled scenarios with the same reusable mechanism):

- At least one successful movement Action with a changed position.
- At least one completed **zero-property-diff Event**, plus one genuinely quiet boundary.
- Two lawfully simultaneous Actions resolved in one shared native commit; verify the shared boundary rather than serializing two separate commits.
- A real `MeleeStrike` yielding native damage, practice/effects and a changed HP property, with correct causal Action/Effect correspondence. Literal ID equality across distinct simulation instances is not required.
- A lawful failed/unproductive attempted Action **if representable without forcing scripted rolls or changing rules**. If not reached under the fixed seed, choose a documented legal fixed-seed fixture or explicitly mark that branch unproven; do not fake a failure.
- At least one boundary after the strike and queries for **several intermediate times**, including before/after damage, an Event-only boundary, a quiet boundary and the simultaneous boundary.
- Preserve and compare *the observer-specific knowledge actually represented by this fixture* (directed awareness). Do **not** claim full observer evidence/belief-history fidelity unless those native ledgers are genuinely used and compared; document the untested parts.

**Historical playback fidelity:** For every supported field in the declared projection, compare canonical values and *presence vs absence* with the original native state at every tested time. Compare the *semantic correspondence* of ordered Events and Effects, Action types, parent/actor/target, timing, outcomes, causal source and recipient relationships, associated change paths and per-boundary grouping. Normalize or map generated Event/Effect IDs consistently before asserting equality. Assert equal full hashes only for canonical projections with the agreed ID normalization; do not equate arbitrary generated ID strings with authoritative facts. Expose an inspectable time-indexed timeline/report; support choosing a boundary from CLI or API. Historical native `CommittedBoundaryRecord` object reconstruction is **not automatically required** if a bounded historical-query/read model gives semantically equivalent results for the tested queries. Explicitly identify native query APIs that remain unsupported; never claim they are restored.

**Deterministic native replay fidelity:** Run the recording and replay in separate Python OS processes, using the pinned compatible source/rules/definitions and private RNG state. Re-submit only recorded legal *inputs*, advance native Actions, then compare each actual native boundary receipt, Action/Effect *causal correspondence* and ordering, pertinent current state, observer-specific state, and RNG cursor to the recorded control. The same-version deterministic re-execution test may compare RNG results exactly; it must not imply cross-version reproducibility. Check the future branch after the selected checkpoint against uninterrupted native progression (no historical Action executed again during resume). If exact equivalence is impossible due to missing declarations, RNG ownership or native APIs, pinpoint it and demonstrate the strongest honest subset.

**Tampering / omissions:** Refuse missing/reordered/duplicate commits, wrong preimages, inconsistent timestamps, duplicate or ambiguously mapped Action/Effect identities *within a logical Encounter*, broken cross-references, altered outcomes/effect contents or causality, unexpected property paths, and mismatched compatibility. A consistent bijective renaming of generated IDs in a separate replay is not corruption. Validation must reject without silently mutating live state. Do not assert byte-identical Python runtime graphs as the fidelity criterion; use a documented semantic equivalence projection, and say exactly what it excludes.

## Performance and representation

Measure for the **same headless fixture**: initial-state bytes, full snapshot bytes, delta/Event history bytes, bytes per meaningful and quiet boundary, historical playback time, deterministic re-execution time, and fresh-process resume time where measured. Count actual property changes and Events separately; do not compare differently configured Arena fixture totals as a controlled compression ratio. Show whether the reconstruction architecture can represent quiet spans without repeating unchanged entity properties. Never suppress real time-dependent state changes merely to improve metrics.

Keep results machine-readable (canonical JSON or similarly simple format), with a human-readable concise replay transcript. No interactive UI is necessary. Preserve strict, versioned compatibility and no hidden dependencies on NPC-generation behavior.

## Acceptance test

This assignment is accepted when a **separate-process** historical playback independently reconstructs the same supported native state and Event timeline at all requested boundaries, and a **separate-process re-execution** through the real native resolver matches the control's actual state, Event/Effect semantic relationships (modulo a validated bijective renaming of generated IDs), Action outcomes, per-boundary grouping and RNG cursor at every tested boundary under pinned matching rules. Preserve zero-diff Events, legitimate quiet time, a consequential combat change, and an atomic two-Action batch; show negative/tamper rejections and exact scope exclusions. Demonstrate no Arena dependencies or production persistence changes. Otherwise report explicitly **partial** rather than presenting terminal hash equality as faithful replay.
