## Objective and definition of done

Deliver a **real, user-playable generated Arena Encounter in the shipped browser interface**, not only synthetic native tests and browser HTTP fixtures. A user must be able to generate or select a legitimate Encounter, inspect what their Being knows, select and complete meaningful supported Actions, see the consequences, and Save/Load the Encounter without regeneration. Existing Action primitives and one-second simultaneous-resolution rules remain authoritative.

The immediate problem is persistent in U-CAP-001 through U-CAP-006 live Chrome checks: a generated Arena opens, but the Action panel often reports **“unknown from player-authorized evidence”**, preventing manual demonstrations even though test-authored HTTP scenarios successfully execute the same Actions. Determine whether this is genuinely missing native source facts, incomplete observer evidence/projection, the wrong UI interaction point, or a real admissibility/Action catalog defect. Do **not** fix it by disclosing objective Reality, manufacturing an NPC skill, or weakening native validation.

**Minimum successful end-to-end demonstration:** in an ordinary running browser, the player can (1) create/select a reproducible legitimate Arena scenario with genuinely represented actionable facts; (2) execute at least two distinct supported Action types in a consequential sequence (for example Draw/Ready then Strike, or Disarm then Pick up, or a prepared Throw), with actual Encounter time progressing; (3) see the actual result, identity/position/custody/condition as personally observable; and (4) save the state and recover the same Encounter in a fresh process, then legally continue. Preserve the ordinary generator experience and do not silently swap in a test NPC.
