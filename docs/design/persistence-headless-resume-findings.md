# Headless native Encounter resume proof

**Disposition:** a bounded, executable native-resume slice for the still-ACTIVE U-PER-SCALE-001 program. This does not replace production `/12`; that path was not changed. The implementation is [`examples/native_headless_resume.py`](../../examples/native_headless_resume.py), built on the accepted initial/delta recorder in [`examples/encounter_delta_headless.py`](../../examples/encounter_delta_headless.py), with focused tests in [`tests/test_native_headless_resume.py`](../../tests/test_native_headless_resume.py).

## Problems first

- The checkpoint is deliberately narrow. It restores one authored two-Being Encounter with a Dagger, fixed `Human`/`Dagger` Library definitions, settled Run/Delay history, no pending/cancelled Action, no open Choice, and one subsequent native Dagger thrust. Other historical Action families, arbitrary Object types, unsettled Choice programs, active pending Actions, Arena lifecycle, and personal-history objects fail closed or are not generated by this fixture.
- Historical completed Action/Event facts and initial+delta history are losslessly retained in the experimental artifact, but old `CommittedBoundaryRecord` receipt objects are **not** rebuilt into the live Encounter. The native restore-owner hook rejects a nonempty prior native receipt list rather than fabricating one. The tested future intervals do create ordinary native receipts and match the uninterrupted branch. Historical native receipt-query compatibility remains outside this bounded slice.
- Definitions are not embedded as a second copy: a compatibility digest covers the Python runtime version, all `src/*.py`, `src/config/*.json`, and Encounter rule Markdown. Restore then loads the matching checkout Library and checks the Human and Dagger profiles against the saved current profile. The artifact is not independently portable away from that exact runtime/source/config/rules bundle.
- This is a small proof, not a production persistence architecture or benchmark claim. It does not establish generic native graph reconstruction, Crash/atomic file replacement, longer combat reliability, or any `/12` migration.

## Demonstrated result

The artifact is validated before native graph construction. A distinct OS process reconstructs Universe and Encounter objects, materializes historical Run/Delay Event identities without resolving those Actions again, binds the narrowly scoped native restoration owner, and advances by ordinary `Encounter.step()` and the existing transactional publisher.

The resumed branch schedules `action-native-dagger-strike` at boundary 4 using Ada's represented Dagger and the ordinary `MeleeStrike` resolver. Its native proposal succeeds (`normal`), proposes a `DamageEffect` of 4 body HP against Bram, and proposes Dagger practice. Atomic commit at boundary 8 changes Bram's HP from 10 to 6. ## Field closure and readers

This table is the entire supported checkpoint contract, not a universal field registry. Source links identify the native consumers that motivated each field group.

| Serialized property / record | Status | Native reader and restore treatment |
|---|---|---|
| Encounter stable ID, DC, ordered participant IDs, time/start time, last processed boundary, coordinator/interval cursor, initiated flag | Required | [`Encounter.step`](../../src/encounter.py), scheduler and [`step_transactionally`](../../src/transactional_progression.py). Restore constructs at the saved cursor and checks every cursor agrees; only a quiescent integer boundary is supported. |
| Pending and cancelled Action IDs | Required, empty in this closure | Encounter scheduler / Choice validation. Any nonempty value is rejected; no unresolved work is dropped. Finished IDs are restored exactly. |
| Being ID/type/name and `Human` definition reference | Required | Universe registry, Action actor/target lookup. Definition key and source/config/rule digest bind immutable template facts. |
| Being position, HP, armor ID, body-part custody, states, posture, size category, hex facing, discrete and Q/B fatigue, physiology ID, represented sphere geometry | Required | [`MeleeStrike`](../../src/melee_combat.py), Being readiness, damage/armor, movement and core spatial readers. Values are serialized, restored and compared before binding. Only authored sphere geometry is decoded. |
| Abilities, skills, weapon skills, skill experience/baselines/use history, strategy | Required for future strike and practice | Melee eligibility, attack/defense, practice publication. Native `SkillUse`, `BatchSkillUse`, candidate-practice and effect-identity records are explicitly encoded/decoded; unsupported dataclasses fail closed. |
| Personal history | Excluded; must be null | It has separate provenance/history semantics and is not read by this scenario. A non-null value is rejected. |
| Ordered possessions/weapons, Object IDs, parent, definition key, current HP/profile/attacks, positions, geometry and derived hand occupancy | Required | Native object registry and weapon readiness/damage; stable IDs are validated against all custody references. The only Object type accepted is the fixture's Dagger `WeaponInstance`. |
| Per-observer awareness | Required | `Encounter.awareness` and observation-facing state. Observer keys and targets must refer to existing Beings; maps remain separately keyed per observer. This is current awareness only, not a general evidence ledger. |
| RNG owner/cursor | Required | Existing transactional publication and native Action evaluators. The exact Python RNG state is restored; no reseed occurs. |
| Settled ChoiceBook, registered prepared packets, closed draft IDs, finished states/counter; Universe schedule revision | Required even though quiescent | ChoiceBook declaration and Encounter scheduler. Historical packets and Action declarations are reconstructed and validated by the restore-owner hook; open reservations/tokens/paused programs, priority penalties and other origins are rejected. |
| Prior Run/Delay Action and Event IDs, parent/actor/target, start/end, outcome, proposal/effect data, lifecycle and committed effect identities | Required historical facts | Universe event lookup, Action history and this artifact's replay. These are materialized as native Event objects but are **not** resolved again. Historical `CommittedBoundaryRecord` objects are not reissued. |
| Initial state and each ordered boundary delta/event record, including quiet and zero-property-effect commits | Required durable history | Independent `replay()` validates chronology, before-value/presence preimages and each boundary digest; checkpoint snapshot must equal reconstructed state. |
| Immutable config/rules/source definitions | External, exact compatibility dependency | Digest-checked checkout/config/rule files are used to rebuild the matching Library. No current or newer NPC Generator facts are consulted. This is pinned-checkout reproducibility, not self-contained portability. |
| Locks, active transaction flags, Python object addresses, GUI/browser/session/controller state | Rebuilt or absent | These are process-local and not authoritative. Only the existing Choice lock identity relation is re-established by binding; no Arena runtime is imported. |
| Other Encounter/World fields, receipts, arbitrary historical Event types, pending choices/actions, entity births/removals | Excluded from supported closure | No reader needed for the tested next boundaries. Unknown field/type, dangling reference, cursor mismatch, unsupported Action family, or unmodeled personal history refuses rather than being silently discarded. |

## Integrity, measurements and execution

Strict decode rejects duplicate JSON keys, malformed/nonfinite JSON, unknown top-level or state/Being/Object/Encounter/Event/Choice fields, wrong schema, bad integrity digest, incompatible Python/source/rules/config, malformed state closure, dangling IDs/custody/awareness, inconsistent cursor/finished queues, malformed native Action history, bad delta preimages, missing/reordered boundaries and checkpoint/delta mismatch. Validation completes before constructing Universe or Encounter. Native restore then checks definitions, profile values, Choice declarations and the entire projected current state before enabling progression. Tests patch Universe construction to prove malformed cases fail first.

Canonical UTF-8 JSON sample at boundary 4: **39,062 bytes total**. Components are measured separately; Event and action-history values are subcomponents already included in the enclosing delta/checkpoint bytes, not additive rows.

| Component | Bytes |
|---|---:|
| Initial state | 9,020 |
| Boundaries 1–4 delta stream (including Event arrays) | 12,134 |
| Event-array subcomponent of that stream | 5,914 |
| Property-change-array subcomponent of that stream | 5,711 |
| Native resume current-state snapshot | 10,748 |
| Action history subcomponent of checkpoint | 5,910 |
| Choice/scheduler metadata | 708 |
| Compatibility metadata | 190 |
| Embedded definition bytes | 0; definitions are pinned external dependencies |
| Full sealed checkpoint | 39,062 |

A measured fresh child process took 1.77 s wall time including Python startup and native continuation; validation/rehydration took 48.9 ms and reported 51.2 MB peak RSS in that sample (platform `ru_maxrss` units). Five ordinary native step calls were roughly 269–350 ms each in a separate control sample; the boundary-8 damage commit's delta was 19,251 bytes because it retains the complete committed Event/Choice/effect record. Repeated runs are deterministic in substance but timing/RSS are expected to vary. This fixture is too small for broad performance claims.

Focused commands:

```sh
checkpoint_path="$(mktemp)"
.venv/bin/python examples/native_headless_resume.py --write-checkpoint "$checkpoint_path"
.venv/bin/python examples/native_headless_resume.py --resume "$checkpoint_path"
.venv/bin/python -m unittest tests.test_native_headless_resume tests.test_persistence_headless_delta -v
.venv/bin/python -m py_compile examples/encounter_delta_headless.py examples/native_headless_resume.py src/transactional_progression.py
```

Run the first command to produce the boundary-4 file, then invoke the second in a separately launched process to demonstrate restoration and continuation. The checkpoint is temporary experimental data, not a portable or production save.

Latest result: **8 tests passed** (16.783 s); compile and `git diff --check` passed. The suite includes actual fresh-OS-process load and future continuation, exact control comparison, HP damage and receipt identity, reproducible artifact, independent delta replay, zero-diff Event/quiet/simultaneous batch retention, checksum/schema/source mismatch, dangling references, bad preimage, missing/reordered history refusal, and validation-before-construction. The adjacent `.venv/bin/python -m unittest test_transactional_progression -v` first lacked its sibling fixture on `sys.path`; with `PYTHONPATH=tests`, it ran 61 tests: 55 passed, 4 errors and 2 failures in 34.815 s. The four errors are stale tests that schedule overlapping Actions without the adopted acquired Multi-action skill; the two failures expect `UnsupportedEvaluation` during mode selection. None calls the new resume hook, and the hook was added without changing existing progression behavior. These failures were not baseline-reproduced during this bounded task and remain explicitly unresolved. No broad repository suite was run. No production `/12` code or format was changed.
