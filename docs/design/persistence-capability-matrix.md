# Native persistence capability matrix

> Source audit for the revised U-PER-SCALE-001 full native-persistence capability. This is a live-code coverage inventory, not a completion claim. `Arena /12` means the type is admitted by the current generated-Arena checkpoint field gate; it does not imply Arena-independent support. `native_graph_snapshot` uses the closed 159-type field registry; native graph `/2` reconstructs Target rows, EntityInspection contexts, publication receipts and Disarm landing indexes from authenticated native history rather than serializing those projections twice. History `/11` retains cumulative listener-owned recipient projections and exact pre-movement boundary-zero Entity state when captured; strict `/1`–`/10` migrations preserve unavailable initial Entity facts as unavailable. Selected native Action, movement, combat, Group, observer and reproduction families pass full continuation scenarios; the matrix remains open for unsupported family/history readers and application Save/Load cutover. Rows are derived from the live closed field registry and checked against the current `/12` allowlist.

## Current production boundary

- Native closed-field catalog: 159 types in `src/checkpoint_fields.py` (`FIELD_ADAPTERS`).
- Executable `checkpoint_inventory._TYPES` now includes the same 159 reviewed types. `test_executable_native_type_registry_matches_all_reviewed_field_adapters` prevents type/field-registry drift; this admits the four previously omitted typed records but does not imply semantic closure or restoration readiness.
- Current production `/12` snapshot admits 104 domain types plus five structural container types via the compatibility shim `src/arena_native_snapshot.py` (`_ARENA_TAGS`); its production capture still requires a generated Arena and Arena-owned/exclusive Encounter RNG cursor.
- `/12` persistence contract is currently rooted in `src/arena_persistence.py` and `src/arena_history_segments.py`; restoration reassembles the graph and calls `arena_native_snapshot.restore()`, which binds Arena-specific progression/receipts. It is not a general native persistence API.
- `src/checkpoint_inventory.py` still advertises a non-ready diagnostic candidate; `CheckpointCandidate.require_complete()` rejects. Native Save uses explicit closed-field capture, `src/checkpoint_adapters.py` owner recipes, strict `src/native_graph_snapshot.py` graph `/2` restore, and the authenticated `src/native_history.py` recorder/query path. The `/2` writer excludes duplicate Target interval records and, for eligible histories without observer-owned receipt maps, omits all per-boundary `PublishedInterval` and `CommittedBoundaryRecord` nodes and reconstructs them from native history. Observer-heavy receipts retain their graph projections until shared-account alias/interleaving facts can be rebuilt losslessly. Exact prior full-native graph `/1` fingerprints remain strict migration inputs. Production `/12` capture/read/write is unchanged. `src/native_persistence.py` reads accepted generated-Arena `/10`–`/12` archives through strict legacy decode plus native graph restore. With an explicit pristine-start selection of native transactional mode, `/10`–`/11` files export to native format, strict-load and continue through a legal first native Choice; generated `/12` first-Choice state also has native export/load/canonical-resave evidence. No Action is synthesized during migration. Only tested family closures may be treated as supported; full receipt-history parity, crash-recoverable history journaling and production Save/Load cutover remain open.
- History `/11` captures the true initial EntityInspection projection from the first validated pre-action transaction snapshot; `initial_entities_available` is explicit and strictly validated. `test_initial_history_precedes_first_boundary_movement_and_survives_fresh_load` checks authored position before the first committed movement, then checks the committed boundary and strict fresh-process continuation. `test_native_history_v10_save_migrates_without_inventing_initial_entities` strictly migrates a `/10` native Save, verifies boundary-zero unavailability and committed query parity, continues in a fresh process, and checks canonical migrated Save→Load→Save. Legacy `/1`–`/10` history retains its historical first-receipt delta anchor and reports no boundary-zero Entity fact; it is never inferred from the restored current graph.
- “Not admitted” below means no current `/12` capture/restore evidence; no inference that the native runtime type is impossible to reach. This matrix must be upgraded with per-scenario tests as each general native family is implemented.

## Interpretation and next test gate

### Schema `/9`: exact initial scheduler and Choice state

History `/9` distinguishes an authenticated initial QueueProjection from older records whose `initial_schedule` came from the first committed receipt rather than the pre-commit cut. A native pending Save captures the exact pending/finished/cancelled queues, registered Action metadata, reservations, Action/Choice lifecycle states, and scheduler revision before the first commit; a fresh process resumes that baseline without re-evaluating earlier work. Strict `/1`–`/8` upgrades retain their old projection internally as the first delta's replay anchor, mark boundary-zero availability false, and never expose it as time-zero fact. A legacy `/12` graph imported after commits also remains unavailable rather than substituting later scheduler state. Upgrade deep-copies authenticated input so adding schema fields cannot invalidate the source digest. `schedule_at(0)` returns `None` when the source fact is unavailable.

Evidence: `test_first_commit_retains_exact_precommit_choice_and_queue_baseline` compares the recorded boundary-zero Choice/queue with the pre-commit native source; `test_multiple_action_choice_and_simultaneous_touch_resume_from_initial_save` compares the same projection after strict fresh-process Load and native continuation.
