# Encounter persistence sufficiency inventory

This is a source traceability aid for U-PER-SCALE-001, not a second task register. It records the current generated-Arena contract and separates next-boundary inputs from durable historical evidence. The classifications are based on live readers and restore validation, not on Python class names alone.

## Current checkpoint composition

`GeneratedArenaSession.save_encounter_bytes()` calls `arena_native_snapshot.capture()` and `arena_persistence.encode()` ([session boundary](../../src/arena_browser_session.py), [native snapshot](../../src/arena_native_snapshot.py), [portable wrapper](../../src/arena_persistence.py)). Capture currently delegates to the general field walker in `checkpoint_inventory._Inventory`; it serializes the reachable Universe/Encounter graph, current RNG and every included collection. `arena_native_snapshot.restore()` rebuilds process-local locks, Choice signatures, anchors, registration identity and RNG ownership, then runs `inspect_encounter()` over the entire committed boundary list before exposing the loaded session.

The earlier monolithic v5 wire exceeded the unchanged strict one-million-node limit at t=91 and kept growing while combat was already terminal. That format is superseded. The current `/11` portable archive separates a resumable snapshot, a version-bound immutable definition table, and ordered one-boundary history segments. The prior `/10` measurements are retained in the report as migration-era evidence. The current writer validates each document separately and enforces aggregate node and byte bounds across the full archive. Exact `/11` measurements and tests are in the [active engineering report](../reports/U-PER-SCALE-001-report.md).

The split does not claim that every remaining snapshot node is a hand-authored domain row: current Being/Object/Encounter values still pass through the existing closed native graph adapter. It removes immutable `*Definition` records and their exclusively owned subgraphs from the resume snapshot, storing them once in `definitions.json` under the captured implementation/rules fingerprint; instances keep references to those exact records. It also removes the unbounded historical prefix from the snapshot. Session, RNG, object custody/equipment, current observer evidence, pending Actions, scheduler registrations and unresolved choices remain current-state fields. The adapter carries an explicit allowlist of append-only native fields; each one-boundary segment stores its attachment roots and the graph closure reachable from that new fact, while the snapshot keeps stable list/owner IDs with empty history-list contents. On Load the archive verifies a canonical manifest, path set, member digests, definition roots, segment order, cursor, field counts, structural bounds and cross-references, then reassembles the exact inventory and calls the ordinary strict native loader. No history is pruned and no simulator state is regenerated.

### Measured source of the initial snapshot

A source-level t=0 capture (5×5 Arena, 10,000 XP, generated player and opponent) produced a 49,179-node resumable inventory, a 624,687-byte snapshot, one boundary segment and 458 bytes of history. The graph's largest exact-type groups were 1,670 ordered-map nodes, 274 list nodes, 141 WeaponDefinition nodes, 31 each of Speed, Abilities, States, Skills and BeingDefinition nodes, 27 ObjectDefinition nodes and 20 ArmorDefinition nodes. Only two BeingInstance nodes were present. Thus the old 50,000-node starting cost was largely static library definitions plus recursive dictionary/container wrappers, not the two live Beings alone.

The targeted split removes committed interval receipts, per-Target interval receipts, fatigue frames and completed observation evidence from the resume-only representation. Completed Action Event objects are still represented in the current graph snapshot even though most are historical; this and static shared-definition extraction are the remaining candidates for reducing snapshot growth when more Actions resolve. The generic native inventory graph is not yet a hand-authored Being/Object row model. The report therefore distinguishes demonstrated history-prefix removal from remaining snapshot-normalization work. Do not describe 68,074 snapshot nodes as the whole of future-state information: it includes current configuration/definition structures accepted by the existing version-bound adapter.

## Design consequence

The required boundary is a compact current-state snapshot plus shared immutable definitions and ordered independently validated committed-history segments. The `/11` Arena archive implements that split for an explicit allowlist of immutable definition types and interval, Target, fatigue, skill-use, projectile and observer history lists. It verifies canonical manifest/member digests, definition roots, entry paths, segment order, snapshot cursor, attachment owners and field counts, per-document depth/node limits, aggregate decoded bytes/nodes, and strict native compatibility before reassembling the exact inventory through the existing production restore path. Missing, extra, altered or truncated history or definition data refuses Load before mutating the active session. The browser transports the self-contained archive as an opaque file.

## Current measurement and remaining normalization

The lawful generated-Arena extended scenario resolves 64 in-range Feints at 0.2 m using ordinary attack rolls, then resolves a 65th Feint. Feint is nondamaging by rule; the test asserts receipts are `success` or `failure`, preserves HP, and does not suppress any damage-capable Action. At t=131 it then holds Beings, equipment and Action count steady for 169 more native boundaries. The `/11` snapshot is 40,330 nodes / 546,110 bytes at both t=131 and t=300; the immutable-definition table is 51,921 nodes / 560,106 bytes; the 169 history segments increase history from 5,655,810 to 12,518,028 bytes. The t=300 archive is 2,974,473 compressed bytes with 13,624,244 decoded snapshot+definition+history bytes. A fresh OS process strictly loads t=300, immediately saves byte-identically, advances to t=301 and matches the uninterrupted run byte-for-byte. The latest verified run took 283.812s; export 4.327s; fresh-process load and exact resave 18.019s; measured process peak RSS 285,343,744 bytes. The 15-field omission itself saves only 853 wire bytes / 59 nodes, establishing that runtime locks/caches were not the main size contributor. The report contains the complete output and test command.

This is a measured plateau for the **resume-only document** in a generated two-Being Arena with 65 represented Action objects. It is not a claim of constant total storage: committed history grows with every native boundary. The native runtime read fence uses an identity sequence for closed frozen history records and a full content read for mutable fatigue frames; strict Save/Load still validates all history records and fingerprints. The earlier 5×5 t=0 fixture measured 49,179 nodes/624,687 bytes. The separate 10×5 empty-loadout diagnostic measured 637,923 native bytes and has a full top-ten canonical-row attribution above. Those distinct fixture measurements should not be compared as a growth pair.

The portable snapshot is still an adapter-built native graph, not an explicit domain-row state document. Completed Action/Event instances remain in that snapshot even though their committed receipts and interval facts are also in history; their current readers include Encounter ChoiceBook/Multiple-action history, Feint follow-up validation, native inspection and history conversation. They have not yet been replaced with stable history references. Thus the archive removes repeated boundary prefixes from the resumable document and is lossless, but it does not yet satisfy the addendum's full normalization goal. Structural sharing of frozen equal values is a safe, measured reduction, but it does not change this architectural limitation. History is reassembled once at Load for the closed native adapter. `/11` separates immutable definitions into `definitions.json`; at t=300 the resume document is 546,110 bytes / 40,330 nodes and definitions are preserved separately at 560,106 bytes / 51,921 nodes. Reassembly remains eager: t=300 fresh-process Load+exact-resave takes 18.019s and 285,343,744 peak RSS in the latest run. A one-pass history-row ownership grouping now avoids rescanning every graph row once per history segment during export, but still produces the full portable archive on each explicit Save. This is not an incremental on-disk commit journal.

An explicit alternative already exists only as an incomplete adapter, not as a production Save/Load replacement. A read-only t=0 probe of `capture_checkpoint_candidate(..., native_adapters=True)` returned both `bounded_run_spot_closure_verified` and `semantic_closure_adapter_incomplete`. The source-linked [`RUN_SPOT_FIELD_CLOSURE`](../../src/checkpoint_fields.py) documents that the recipe does not close unrelated Library dictionaries, all Universe aliases, receipt reissuance/anchors or general restoration. The current Arena has broader Actions and receipt relationships than the certified Run/Spot slice. A safe field-minimal domain-row replacement therefore needs new, narrow adapter/rehydration coverage; the current closeout does not claim that work is complete.

The current native snapshot also has a separate fail-closed field vocabulary check. `arena_native_snapshot._validate_arena_field_schema` requires every serialized native type to have an explicit allowed/required `FIELD_ADAPTERS` entry and rejects unknown fields on capture, encode and current-schema decode. Legacy schemas remain compatibility-migrated by their versioned path and then undergo strict inventory validation. This prevents a new incidental runtime field or type from silently expanding the save contract. It guards the existing graph; it is not the domain-row representation requested by the addendum.

Portable export builds a complete ZIP in a private in-memory buffer and returns bytes only after the manifest, every segment and the finished ZIP are available. The archive-transaction regression injects an exception while writing a history member, verifies the live candidate/committed inspection remain unchanged, then retries and proves exact archive bytes. A second worker is terminated with `os._exit(73)` during history-member writing; its previously completed `.uarena` remains byte-identical and a fresh recovery process strict-loads/resaves that artifact exactly. This covers interrupted artifact construction, not autosave. There is no persistent append journal: progress after the last user Save is not durable until another complete artifact is downloaded.

The supported `ObjectRegistry` world-object curve covers two Arena Beings plus 18 and 198 extra **unplaced, non-participating** native Being instances; each extra Being references the existing Dagger definition through its Weapon inventory. At 2/20/200 registry Beings the `/11` snapshot is 145,576 / 302,843 / 1,879,948 bytes (11,621 / 24,294 / 151,014 nodes), and the separate definitions table is 551,452 / 709,564 / 2,290,684 bytes; strict fresh-process Load and exact resave pass at every size. Create/save peak RSS is 51,494,912 / 56,672,256 / 114,114,560 bytes. This demonstrates world-registry object persistence through 200 instances without asserting that all 200 take part in the two-person Encounter or have locations, group memberships or observer knowledge. The Arena's exact two-participant/perception limit still blocks a larger active encounter curve.

The current generated Arena realizes two Beings as Encounter participants: [`ArenaInitializationCandidate.participants`](../../src/arena_initialization.py) is explicitly a two-entry tuple, and [`initialize_arena_perception`](../../src/arena_perception.py) rejects an Encounter whose participant count is not exactly two. The 20/200 persisted object-register fixture above uses no extra participant, location or observer facts; it does not demonstrate larger active encounters. No army-scale or general multi-Encounter claim follows from these measurements. Memory was measured in fresh worker processes for both the world-size curve and t=300 history test. A real served Chrome Save and Open-file Load of a portable t=0 Arena archive succeeded in this continuation; HTTP/session tests separately cover the longer checkpoint and transactional rejection. U-PER-SCALE-001 stays ACTIVE until current-state normalization, supported larger active-Encounter realization and practical long-history load costs are resolved.
